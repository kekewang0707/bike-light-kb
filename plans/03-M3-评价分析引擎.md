# M3 — 评价分析引擎

**目标**：用 LLM 从评价原文中提取结构化知识（卖点、使用场景、痛点、用户画像），向量化存入 ChromaDB。

**依赖**：M1（数据模型层）

**目录**：`analysis/`（本模块负责评价文本分析部分，图片分析见 M4）

## 2. 核心类设计

### 2.1 LLMClient (llm_client.py)

```python
class LLMClient:
    """LLM API 封装，支持多 provider"""

    def __init__(self, provider: str = "deepseek"):
        """
        从环境变量读取 API Key
        支持 provider: deepseek / qwen / openai-compatible
        """

    async def chat(
        self,
        messages: List[dict],
        temperature: float = 0.3,
        max_tokens: int = 2000,
        response_format: str = "json_object"
    ) -> dict:
        """发送请求，返回解析后的 JSON。带自动重试(最多3次)。"""

    async def chat_batch(
        self,
        prompts: List[str],
        system_prompt: str,
        concurrency: int = 5
    ) -> List[dict]:
        """批量请求，信号量控制并发。单个失败不影响其他。"""
```

### 2.2 ReviewAnalyzer (review_analyzer.py)

```python
class ReviewAnalyzer:
    """评价语义分析器"""

    def __init__(self, llm: LLMClient, db_session: Session):
        ...

    SYSTEM_PROMPT = """你是自行车灯品类的电商分析专家。
分析用户评价，提取结构化信息。返回严格 JSON 格式，不含任何额外文本。"""

    EXTRACT_PROMPT = """
分析以下自行车灯的用户评价，提取：

1. **卖点 (selling_points)**：用户明确好评的产品特性，每项含：
   - "aspect": 具体特性（如"亮度""续航""安装方便"）
   - "mention": 用户原话引用（10字以内）
   - "sentiment": "positive" | "neutral"

2. **使用场景 (use_scenes)**：用户实际使用场景，每项含：
   - "scene": 场景描述（如"夜间山路骑行""城市通勤"）
   - "detail": 用户原话引用
   - "confidence": 0.0-1.0（推断置信度）

3. **痛点 (pain_points)**：用户不满或吐槽，每项含：
   - "aspect": 问题点（如"续航不够""支架松动""进水"）
   - "mention": 用户原话引用
   - "severity": "high" | "medium" | "low"

4. **用户画像 (user_profile)**：
   - "rider_type": 骑行者类型（通勤/运动/长途/外卖/不确定）
   - "bike_type": 车型（山地车/公路车/折叠车/电助力/不确定）
   - "concern_priority": ["价格敏感"/"性能优先"/"品牌倾向"/"性价比"]

评价内容：{review_text}
商品评分：{rating} 星（满分5星）
"""

    async def analyze_single(self, review: Review) -> ReviewAnalysis:
        """分析单条评价，提取结构化结果"""

    async def analyze_batch(
        self,
        reviews: List[Review],
        batch_size: int = 10,
        concurrency: int = 3
    ) -> List[ReviewAnalysis]:
        """批量分析，内部分批 + 限速"""

    async def analyze_product(self, product_id: int) -> ProductReviewSummary:
        """分析某商品所有评价，汇总洞见"""

    def save_results(self, results: List[ReviewAnalysis]):
        """分析结果写入 review_analysis 表"""
```

class BatchRunner:
    """批量任务执行器 — 分批调用 + 限速 + 重试"""

    def __init__(
        self,
        llm: LLMClient,
        batch_size: int = 10,       # 每批条数
        concurrency: int = 3,       # 并发数
        max_retries: int = 3,       # 失败重试次数
        rate_limit_rpm: int = 30    # 每分钟请求数上限
    ):
        ...

    async def run(
        self, items: List[Any], process_fn: Callable
    ) -> BatchResult:
        """
        分批执行 process_fn，返回成功/失败统计。
        失败项自动重试，3次仍失败则记录并跳过。
        """

## 5. 实施步骤

| 步骤 | 内容 | 产出 |
|:---|:---|:---|
| 1 | 调通 DeepSeek API → `llm_client.py` | 可调用的 LLM 客户端 |
| 2 | 手写 5 条自行车灯评价，调优 Prompt → `review_extract.py` | 准确率 > 85% 的 Prompt |
| 3 | 实现 `review_analyzer.py` — 单条 + 批量分析 | 评价分析能力就绪 |
| 4 | 实现 `batch_runner.py` — 分批+限速+失败重试 | 大批量稳定运行 |
| 5 | 实现 `spec_normalizer.py` — 规格参数标准化 | 不同品牌的规格可对比 |
| 6 | 跑通全量评价分析（约5000条评价） | 评价语义数据库 |
| 7 | 抽样 100 条人工核验，调整 Prompt | 质量抽检报告 |

## 6. 关键设计决策

- **低价 LLM 优先**：DeepSeek 成本约为 GPT-4 的 1/10，适合大批量评价分析
- **response_format: json_object**：强制 JSON 输出，配合 Pydantic 校验，不合规自动重试
- **批量+限速**：避免 API 限流。每批 10 条，并发 3，每分钟上限 30 次请求
- **评价原文引用 (mention)**：要求 LLM 保留用户原话，方便文案同学直接引用
- **结果存 PostgreSQL**：分析结果写入 `review_analysis` 表（JSONB 字段），后续通过 M5 知识库同步到 ChromaDB
