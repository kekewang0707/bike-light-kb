# M4 — 图片分析管道

**目标**：对商品图片进行 OCR 文字提取、多模态描述生成、CLIP 向量化，让图片可被语义检索。

**依赖**：M1（数据模型层）、M2（爬虫引擎 — 需先补齐 ProductImage 记录写入）

**目录**：`analysis/image/`

---

## 0. 前置工作 — 补齐 ProductImage 记录写入（M2 补丁）

**问题**：当前 `ImageDownloader` 只将图片写入磁盘，不创建 `ProductImage` 数据库记录。`product_images` 表始终为空，M4 无数据可分析。

**方案**：在 `crawler/downloader.py` 的 `download_batch()` 完成后，将成功下载的图片信息批量写入 `product_images` 表。

```python
# crawler/downloader.py 新增方法

class ImageDownloader:
    def __init__(self, ...):
        ...
        self._image_crud = CRUDBase(ProductImage)

    def sync_product_images(self, tasks: List[ImageTask], success_paths: List[str]):
        """下载完成后，将成功下载的图片写入 product_images 表。
        
        按 (product_id, image_url) 去重，已存在则更新 local_path。
        """
        session = next(get_session())
        try:
            success_set = set(success_paths)
            for task in tasks:
                if task.local_path not in success_set:
                    continue
                self._image_crud.upsert_by(
                    session,
                    filters={"product_id": task.product_id, "image_url": task.url},
                    updates={
                        "image_type": task.image_type,
                        "local_path": task.local_path,
                        "sort_order": task.sort_order,
                    },
                )
        finally:
            session.close()
```

同步调用 `ImageDownloader.sync_product_images()` 置于 `CrawlerEngine.run()` 的 Phase 3 末尾。

## 2. 核心类设计

### 2.1 OCRExtractor (ocr.py)

```python
class OCRExtractor:
    """商品图片 OCR 文字提取。
    
    优先使用 PaddleOCR（中文准确率最高），若安装失败则降级为 EasyOCR。
    模型懒加载：首次调用 extract() 时初始化。
    """

    def __init__(self, backend: str = "paddleocr"):
        """
        参数:
            backend: "paddleocr" | "easyocr"
            若指定 backend 不可用，自动降级到另一个。
        """

    def extract(self, image_path: str) -> OCRResult:
        """提取单张图片文字。"""

    def extract_batch(self, image_paths: List[str]) -> List[OCRResult]:
        """批量 OCR，顺序处理。"""

@dataclass
class OCRResult:
    full_text: str                 # 所有识别文本（空格拼接）
    text_blocks: List[dict]        # [{"text":"800流明亮","bbox":[...],"confidence":0.95}]
    key_phrases: List[str]         # 可能是卖点标签的文字块，如 ["800流明","IPX6防水"]
```

**后端选择策略**：
- macOS 上 PaddleOCR 安装困难时，改用 EasyOCR（`pip install easyocr`）
- 两者 `extract()` 返回一致的 `OCRResult`，调用方无感知
- 在 `__init__` 中检测可用性，日志记录当前使用的后端

### 2.2 MultimodalDescriber (multimodal.py)

```python
class MultimodalDescriber:
    """多模态图片语义描述。
    
    使用 Qwen-VL（通过阿里云 DashScope API）生成图片描述。
    如需切换 GPT-4V，只需修改 _call_api 方法。
    """

    DESCRIPTION_PROMPT = """描述这张自行车灯商品主图：
1. 产品外观（形状/颜色/大小/灯珠数量/显示屏）
2. 安装方式（车把夹装/头盔/座管/绑带式）
3. 展示场景（白底棚拍/户外骑行/夜拍光效/功能对比图）
4. 视觉风格（极简/运动/科技感/复古/户外硬核）
5. 画面中的文字信息（卖点标签、规格标注）

输出 JSON：{"appearance":"...","mount_type":"...","scene":"...","style":"...","text_overlay":"..."}
"""

    def __init__(self, api_key: Optional[str] = None):
        """
        参数:
            api_key: DashScope API key。不传则从 settings.dashscope_api_key 读取。
        """

    async def describe(self, image_path_or_url: str) -> ImageDescription:
        """分析单张图片。内置重试：最多 3 次，指数退避。"""

    async def describe_batch(
        self, images: List[str], concurrency: int = 3
    ) -> List[Optional[ImageDescription]]:
        """批量分析。失败项返回 None，不阻塞其他图片。"""

@dataclass
class ImageDescription:
    appearance: str       # 产品外观描述
    mount_type: str       # 安装方式
    scene: str            # 展示场景
    style: str            # 视觉风格
    text_overlay: str     # 画面文字信息
```

**配置新增**（`config/settings.py`）：

```python
# 多模态 VL
dashscope_api_key: str = ""       # 阿里云 DashScope（Qwen-VL）
```

**重试与容错**（参照 M3 `_fallback_invoke` 模式）：
- DashScope API 超时 60s，最多重试 3 次，指数退避（1s / 2s / 4s）
- JSON 解析失败 → 以原始文本存储到 description 字段
- 单张失败不阻塞批量任务，日志记录并返回 None

### 2.3 CLIPVectorizer (clip_vectorizer.py)

```python
class CLIPVectorizer:
    """CLIP 图片向量化 + 风格聚类。
    
    使用 HuggingFace transformers 加载 CLIP 模型（与项目共用 PyTorch 依赖）。
    M4 只负责生成向量，不直接写 ChromaDB — ChromaDB 写入由 M5 负责。
    """

    def __init__(self, model_name: str = "openai/clip-vit-base-patch32"):
        """
        加载 CLIP 模型。默认 ViT-B/32（最小，CPU 可接受）。
        后期可升级: "openai/clip-vit-large-patch14"

        使用 transformers.CLIPModel + CLIPProcessor，避免引入额外的 openai-clip 包。
        """

    def vectorize(self, image_path: str) -> np.ndarray:
        """生成 512 维 CLIP 向量。shape: (512,)"""

    def vectorize_batch(self, image_paths: List[str]) -> np.ndarray:
        """批量向量化。shape: (N, 512)"""

    def cluster_styles(
        self, vectors: np.ndarray, n_clusters: int = 5
    ) -> StyleClusters:
        """K-Means 聚类，返回每个簇的代表图和风格关键词。
        
        用于全品类风格分析报告，不依赖 ChromaDB。
        """

@dataclass
class StyleClusters:
    n_clusters: int
    clusters: List[StyleCluster]

@dataclass
class StyleCluster:
    indices: List[int]             # 属于该簇的图片在原始列表中的索引
    size: int                      # 该簇包含的图片数量
    top_style_tags: List[str]      # 该簇最常见的风格标签
    representative_indices: List[int]  # 距离簇中心最近的 3 张图片索引
```

**M4 / M5 边界约定**：
- M4：生成向量 → 存入 `ImageAnalysis.clip_vector_id` 为占位符
- M5：读取 `ImageAnalysis` 表 → 向量化已有文本 → 写入 ChromaDB 各 Collection
- M4 不 import ChromaDB，不在 M4 中执行 `save_to_chromadb()` 和 `find_similar()`

## 3. 图片分析流水线

```python
class ImageAnalysisPipeline:
    """端到端图片分析流水线。

    职责：
    1. 从 product_images 表查询待分析图片
    2. 按图片类型分流：主图全量分析，详情图仅 OCR，晒图跳过
    3. 批量去重（跳过已有分析结果的图片）
    4. 执行分析并持久化到 image_analysis 表
    5. 产出分析报告

    Session 管理：调用方传入 session，流水线不负责 session 生命周期。
    参照 M3 中 ReviewAnalyzer / BatchRunner 的协作模式。
    """

    def __init__(
        self,
        ocr: Optional[OCRExtractor] = None,
        describer: Optional[MultimodalDescriber] = None,
        clip: Optional[CLIPVectorizer] = None,
        session: Optional[Session] = None,
    ):
        self.ocr = ocr or OCRExtractor()
        self.describer = describer or MultimodalDescriber()
        self.clip = clip or CLIPVectorizer()
        self.session = session

    # ------------------------------------------------------------------
    # 主入口
    # ------------------------------------------------------------------

    async def analyze_all(
        self,
        limit: Optional[int] = None,
        concurrency: int = 3,
    ) -> ImageAnalysisReport:
        """
        对全部未分析的图片执行分析：
        step1: 查询 product_images 表中无分析记录的图片
        step2: 按图片类型分流
               - 主图 (main):   OCR + 多模态描述 + CLIP 向量化
               - 详情图 (detail): 仅 OCR
               - 其他:          跳过
        step3: 批量分析 + 写入 image_analysis 表
        step4: 全品类 CLIP 聚类 → 产出风格分析报告
        """

    async def analyze_single(
        self, image: ProductImage
    ) -> Optional[ImageAnalysis]:
        """分析单张图片。按 image_type 自动分流。
        
        返回:
            ImageAnalysis ORM 实例（未写入 DB）。失败返回 None。
            与 M3 的 ReviewAnalyzer.analyze_single() 返回模式一致。
        """

    async def recluster(self) -> StyleClusters:
        """重新聚类（新图片入库后调用）。
        
        从 image_analysis 表读取已有 style_tags，
        结合 CLIP 向量做 K-Means 聚类。
        """

    # ------------------------------------------------------------------
    # 内部方法
    # ------------------------------------------------------------------

    def _analysis_plan(self, image: ProductImage) -> List[str]:
        """根据图片类型返回分析计划。
        
        返回: ["ocr", "multimodal", "clip"] 的子集
        
        规则:
        - main:   ["ocr", "multimodal", "clip"]
        - detail: ["ocr"]
        - review: []（跳过）
        - 其他:   ["ocr"]
        """

    async def _analyze_with_retry(
        self, image: ProductImage, analysis_type: str
    ) -> Optional[dict]:
        """带重试的单类型分析。"""

@dataclass
class ImageAnalysisReport:
    """图片分析批次报告 — 与 M3 的 BatchResult 模式一致。"""
    total_images: int = 0
    analyzed: int = 0
    ocr_done: int = 0
    multimodal_done: int = 0
    clip_done: int = 0
    failed: int = 0
    skipped: int = 0
    style_clusters: Optional[StyleClusters] = None
    duration_seconds: float = 0.0
    errors: List[str] = field(default_factory=list)
```

**执行策略（分图片类型）**：

| 图片类型 | OCR | 多模态描述 | CLIP 向量化 | 说明 |
|:---|:---:|:---:|:---:|:---|
| main（主图） | ✅ | ✅ | ✅ | 全量分析 |
| detail（详情图） | ✅ | — | — | 仅提取文字标注 |
| video_cover | ✅ | — | — | 仅提取文字 |
| review（晒图） | — | — | — | 跳过，Phase 4 可选 |

## 5. 关键设计决策

- **仅主图做多模态描述**：详情图数量大、信息密度低，只做 OCR。控制 API 成本（VL 调用昂贵，每次约 ¥0.01-0.05）
- **OCR 双后端**：优先 PaddleOCR（中文最佳），macOS 不可用时降级 EasyOCR。两者返回统一 `OCRResult`，调用方无感知
- **transformers 加载 CLIP**：使用 `transformers.CLIPModel`，与项目 LangChain/PyTorch 共用依赖，避免额外引入 `openai-clip` 包
- **M4 不写 ChromaDB**：M4 只生成向量，存储到 `ImageAnalysis` 表的 JSONB / 向量占位符中。ChromaDB 的 Collection 创建和写入由 M5 统一负责，避免两处维护 Collection schema
- **懒加载模型**：OCR / VL / CLIP 模型在首次使用时加载，避免启动时占用大量内存
- **重试与容错**：VL API 调用内置 3 次重试（参照 M3 `_fallback_invoke` 模式）；单张失败不阻塞批量任务
- **Session 由调用方管理**：`ImageAnalysisPipeline` 持有 session 引用，生命周期由外部（BatchRunner 或脚本）控制。与 M3 保持一致的协作模式
- **产品图片记录**：前置步骤 0 补齐 `ImageDownloader → ProductImage` 写入链路。按 `(product_id, image_url)` 去重，下载成功后 upsert 到 `product_images` 表
